# Frontend visual design

Create deliberate interfaces that feel custom-designed for school operations. Prioritize structural clarity, high data density and practical utility. Avoid generic templates and decoration without a purpose. These rules apply to interface creation and visual refinement within the requested scope.

## Icons and copy

- Never use emojis or emoticons anywhere in the interface: text, buttons, alerts, notifications, icons or placeholders.
- Use clean, ultra-minimal vector SVG paths for icons. Prefer the existing icon system and give icon-only controls accessible names.
- Use specific, realistic, synthetic school data and contextual copy when examples are needed. Never use Lorem Ipsum, Feature 1 or generic filler. Keep real application data and working flows intact.

## Typography

- Never use Inter, Geist, Roboto or Space Grotesk.
- Prefer premium system font stacks or professional geometric and neo-grotesque alternatives. Heading options include General Sans, Satoshi, Urbanist or Fraunces for a deliberate serif treatment.
- Body and control options include Switzer or heavily customized Plus Jakarta Sans. Use clean, utilitarian monospace where useful for numbers.
- Keep each view to no more than three distinct font sizes. Establish hierarchy through weight, spacing and alignment as well as size.

## Layout and surfaces

- Use strict grids, persistent structural sidebars for dashboards and crisp structural alignment. Avoid staggered, unaligned elements. Keep navigation and data usable at narrow widths.
- Keep panel corner radii at or below 8px, preferring 4–8px. Avoid oversized rounded containers.
- Separate sections with ultra-faint 1px solid dividers, such as neutral-100 in light mode or neutral-800 in dark mode. Preserve sufficient contrast for controls and focus indicators.
- Use chalk whites, organic light grays or deep matte charcoal tones. Avoid heavy shadows, glowing or neon gradient borders, floating radial lights, background orbs and artificial purple dark-mode palettes.

## Interaction

- Give every interactive cell, button and row an immediate, polished state response, such as a subtle background shift with a precise 150ms ease-out transition.
- Preserve clear hover, keyboard focus, pressed, selected and disabled states where applicable. Respect reduced-motion preferences.
- Keep semantic HTML, labels, keyboard access and visible focus intact when applying the visual rules.
