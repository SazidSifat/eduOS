The temporary cluster was initialized with `/usr/lib/postgresql/18/bin/initdb -D /tmp/eduos-rbac-pg -A trust --no-locale`. Starting it with `pg_ctl` failed because the sandbox denies Unix socket creation. SQL was therefore checked using `/usr/lib/postgresql/18/bin/postgres --single -j -D /tmp/eduos-rbac-pg eduos_test_rbac`. Only synthetic test records were used. Diagnostic logs are under `/tmp/eduos-rbac-*.log`; no development database was migrated or modified.

Standalone SQL checks exercise the actual PostgreSQL engine and constraints, but do not exercise the Drizzle migrator/journal replay, Better Auth sessions, service transactions or concurrent row/advisory locking. Those guarantees still require the supplied integration suite on reachable PostgreSQL. PostgreSQL's own [single-user mode documentation](https://www.postgresql.org/docs/18/app-postgres.html) explicitly distinguishes it from realistic interprocess locking.
